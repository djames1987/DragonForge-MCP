# C-005A — SQLite authority schema and transaction contract
**Phase 0 documentation-only.** Selected delegated detailed design, NOT executed migrations or qualified security. Depends on C-001/002/003/006/008/009, DEC-002–005. SQLite minimum **3.37.0** for STRICT tables. Gateway alone has the writer connection; workers never access DB/WAL/SHM files. See https://www.sqlite.org/stricttables.html , https://www.sqlite.org/foreignkeys.html , https://www.sqlite.org/lang_transaction.html and https://www.sqlite.org/wal.html.

## Database parameters and invariants
- Database path created under private owner ACL; reject symlinks/reparse paths and incorrect permissions; do not automatically create a replacement when an existing store fails integrity or decryption checks.
- Every connection: `PRAGMA foreign_keys=ON` (verify returns 1), `busy_timeout=5000`, `trusted_schema=OFF`. Writer init: `journal_mode=WAL` (verify result), `synchronous=FULL`, `wal_autocheckpoint=1000`. `PRAGMA quick_check` on ordinary startup; `integrity_check` plus `foreign_key_check` before recovery/backup activation. DDL applied under `BEGIN IMMEDIATE`, with explicit `PRAGMA user_version` validation and a matching migration row; do not execute scripts from mutable packages.
- SQL `TEXT` timestamps are fixed UTC RFC3339 with millisecond precision (`YYYY-MM-DDTHH:MM:SS.sssZ`), generated by gateway clock, never worker-supplied. IDs are UUID strings; hash BLOB values are exactly 32 bytes; bearer verifiers are keyed HMAC-SHA256. Every critical mutable row has integer monotonic `revision` where relevant. Audit includes no plaintext secret or tool inputs.
- Binary hashes are SHA-256 bytes, not textual hex; a 64-lowercase-hex digest at external boundaries converts to 32-byte BLOB. Hash canonicalization follows C-002A package byte stream and C-006A RFC8785 I-JSON arguments. Distinct namespace for idempotency: (principal, tool_version_id, key).
- DDL below is the **complete proposed v1 authority-store schema**. Application-level legal transitions and append-only enforcement remain mandatory; SQL constraints alone cannot prove transitions.

## Migration 0001 — schema (documented SQL; DO NOT RUN IN PHASE 0)
```sql
PRAGMA foreign_keys=ON;
PRAGMA trusted_schema=OFF;
PRAGMA busy_timeout=5000;
PRAGMA journal_mode=WAL;
PRAGMA synchronous=FULL;
BEGIN IMMEDIATE;
CREATE TABLE schema_migrations (
  migration_id INTEGER PRIMARY KEY CHECK(migration_id>0),
  checksum BLOB NOT NULL CHECK(length(checksum)=32),
  applied_at TEXT NOT NULL,
  app_version TEXT NOT NULL
) STRICT;
CREATE TABLE store_metadata (
  singleton INTEGER PRIMARY KEY CHECK(singleton=1),
  instance_id TEXT NOT NULL UNIQUE,
  schema_version INTEGER NOT NULL CHECK(schema_version>=1),
  authority_epoch INTEGER NOT NULL CHECK(authority_epoch>=0),
  policy_epoch INTEGER NOT NULL CHECK(policy_epoch>=0),
  recovery_generation INTEGER NOT NULL CHECK(recovery_generation>=0),
  created_at TEXT NOT NULL,
  last_reconciled_at TEXT
) STRICT;
CREATE TABLE clients (
  client_id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL UNIQUE CHECK(length(display_name) BETWEEN 1 AND 128),
  state TEXT NOT NULL CHECK(state IN ('ACTIVE','DISABLED','REVOKED')),
  created_at TEXT NOT NULL,
  revoked_at TEXT,
  revision INTEGER NOT NULL DEFAULT 1 CHECK(revision>=1),
  CHECK((state='REVOKED')=(revoked_at IS NOT NULL))
) STRICT;
CREATE TABLE credentials (
  credential_id TEXT PRIMARY KEY,
  client_id TEXT NOT NULL REFERENCES clients(client_id) ON DELETE RESTRICT,
  key_id TEXT NOT NULL UNIQUE,
  verifier BLOB NOT NULL CHECK(length(verifier)=32),
  pepper_key_id TEXT NOT NULL,
  issued_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  revoked_at TEXT,
  rotation_parent_id TEXT REFERENCES credentials(credential_id) ON DELETE RESTRICT,
  revision INTEGER NOT NULL DEFAULT 1,
  CHECK(expires_at>issued_at)
) STRICT;
CREATE INDEX ix_credentials_client ON credentials(client_id,revoked_at,expires_at);
CREATE TABLE tool_packages (
  package_id TEXT PRIMARY KEY,
  digest BLOB NOT NULL UNIQUE CHECK(length(digest)=32),
  digest_algorithm TEXT NOT NULL CHECK(digest_algorithm='DFMCP-PACKAGE-V1-SHA256'),
  relative_store_path TEXT NOT NULL UNIQUE,
  state TEXT NOT NULL CHECK(state IN ('STAGED','VALIDATED','TRUSTED','ENABLED','DISABLED','REVOKED')),
  created_at TEXT NOT NULL,
  trusted_at TEXT,
  revoked_at TEXT,
  revision INTEGER NOT NULL DEFAULT 1
) STRICT;
CREATE TABLE tool_versions (
  version_id TEXT PRIMARY KEY,
  package_id TEXT NOT NULL UNIQUE REFERENCES tool_packages(package_id) ON DELETE RESTRICT,
  tool_id TEXT NOT NULL,
  semver TEXT NOT NULL,
  entry_kind TEXT NOT NULL CHECK(entry_kind IN ('python','native')),
  entry_point TEXT NOT NULL,
  effect TEXT NOT NULL CHECK(effect IN ('read','write','external')),
  manifest_json TEXT NOT NULL,
  input_schema_json TEXT NOT NULL,
  output_schema_json TEXT NOT NULL,
  timeout_ms INTEGER NOT NULL CHECK(timeout_ms BETWEEN 1 AND 300000),
  max_input_bytes INTEGER NOT NULL CHECK(max_input_bytes BETWEEN 1 AND 1048576),
  max_output_bytes INTEGER NOT NULL CHECK(max_output_bytes BETWEEN 1 AND 4194304),
  max_parallel INTEGER NOT NULL CHECK(max_parallel BETWEEN 1 AND 4),
  idempotency TEXT NOT NULL CHECK(idempotency IN ('none','keyed')),
  UNIQUE(tool_id,semver,package_id)
) STRICT;
CREATE INDEX ix_tool_versions_name ON tool_versions(tool_id,semver);
CREATE TABLE tool_capabilities (
  version_id TEXT NOT NULL REFERENCES tool_versions(version_id) ON DELETE RESTRICT,
  capability_id TEXT NOT NULL,
  PRIMARY KEY(version_id,capability_id)
) STRICT, WITHOUT ROWID;
CREATE TABLE client_tool_grants (
  grant_id TEXT PRIMARY KEY,
  client_id TEXT NOT NULL REFERENCES clients(client_id) ON DELETE RESTRICT,
  version_id TEXT NOT NULL REFERENCES tool_versions(version_id) ON DELETE RESTRICT,
  grant_kind TEXT NOT NULL CHECK(grant_kind IN ('DISCOVER','INVOKE')),
  state TEXT NOT NULL CHECK(state IN ('ACTIVE','REVOKED')),
  granted_at TEXT NOT NULL,
  revoked_at TEXT,
  revision INTEGER NOT NULL DEFAULT 1,
  CHECK((state='REVOKED')=(revoked_at IS NOT NULL))
) STRICT;
CREATE UNIQUE INDEX uq_active_client_grant ON client_tool_grants(client_id,version_id,grant_kind) WHERE state='ACTIVE';
CREATE UNIQUE INDEX uq_grant_version ON client_tool_grants(grant_id,version_id);
CREATE INDEX ix_grants_client ON client_tool_grants(client_id,state,grant_kind);
CREATE TABLE capability_grants (
  grant_id TEXT NOT NULL REFERENCES client_tool_grants(grant_id) ON DELETE RESTRICT,
  capability_id TEXT NOT NULL,
  scope_jcs TEXT NOT NULL,
  PRIMARY KEY(grant_id,capability_id),
  version_id TEXT NOT NULL,
  FOREIGN KEY(version_id,capability_id) REFERENCES tool_capabilities(version_id,capability_id),
  FOREIGN KEY(grant_id,version_id) REFERENCES client_tool_grants(grant_id,version_id)
) STRICT, WITHOUT ROWID;
CREATE TABLE pending_approvals (
  approval_id TEXT PRIMARY KEY,
  intent_id TEXT NOT NULL UNIQUE,
  nonce BLOB NOT NULL UNIQUE CHECK(length(nonce)=16),
  client_id TEXT NOT NULL REFERENCES clients(client_id) ON DELETE RESTRICT,
  version_id TEXT NOT NULL REFERENCES tool_versions(version_id) ON DELETE RESTRICT,
  argument_sha256 BLOB NOT NULL CHECK(length(argument_sha256)=32),
  capabilities_jcs TEXT NOT NULL,
  effect TEXT NOT NULL CHECK(effect IN ('write','external')),
  policy_epoch INTEGER NOT NULL,
  state TEXT NOT NULL CHECK(state IN ('PENDING','APPROVED','DENIED','EXPIRED','CANCELLED','CONSUMED','INVALIDATED')),
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL,
  owner_sid TEXT,
  decided_at TEXT,
  consumed_at TEXT,
  revision INTEGER NOT NULL DEFAULT 1,
  CHECK(expires_at>created_at)
) STRICT;
CREATE INDEX ix_approvals_status ON pending_approvals(state,expires_at);
CREATE TABLE invocations (
  invocation_id TEXT PRIMARY KEY,
  intent_id TEXT NOT NULL UNIQUE,
  client_id TEXT NOT NULL REFERENCES clients(client_id) ON DELETE RESTRICT,
  version_id TEXT NOT NULL REFERENCES tool_versions(version_id) ON DELETE RESTRICT,
  approval_id TEXT UNIQUE REFERENCES pending_approvals(approval_id) ON DELETE RESTRICT,
  argument_sha256 BLOB NOT NULL CHECK(length(argument_sha256)=32),
  state TEXT NOT NULL CHECK(state IN ('ADMITTED','QUEUED','RUNNING','SUCCEEDED','TOOL_FAILED','CANCELLED','TIMED_OUT','CRASHED','UNKNOWN_EFFECT')),
  created_at TEXT NOT NULL,
  started_at TEXT,
  finished_at TEXT,
  predecessor_id TEXT REFERENCES invocations(invocation_id) ON DELETE RESTRICT,
  correlation_id TEXT NOT NULL UNIQUE,
  revision INTEGER NOT NULL DEFAULT 1
) STRICT;
CREATE INDEX ix_invocations_client ON invocations(client_id,created_at);
CREATE INDEX ix_invocations_state ON invocations(state,created_at);
CREATE TABLE idempotency_records (
  client_id TEXT NOT NULL REFERENCES clients(client_id) ON DELETE RESTRICT,
  version_id TEXT NOT NULL REFERENCES tool_versions(version_id) ON DELETE RESTRICT,
  idempotency_key TEXT NOT NULL CHECK(length(idempotency_key) BETWEEN 1 AND 128),
  argument_sha256 BLOB NOT NULL CHECK(length(argument_sha256)=32),
  invocation_id TEXT NOT NULL UNIQUE REFERENCES invocations(invocation_id) ON DELETE RESTRICT,
  created_at TEXT NOT NULL,
  PRIMARY KEY(client_id,version_id,idempotency_key)
) STRICT, WITHOUT ROWID;
CREATE TABLE audit_events (
  audit_seq INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id TEXT NOT NULL UNIQUE,
  utc_time TEXT NOT NULL,
  actor_kind TEXT NOT NULL CHECK(actor_kind IN ('CLIENT','OWNER','GATEWAY','ANONYMOUS')),
  actor_id TEXT,
  operation TEXT NOT NULL,
  subject_id TEXT,
  correlation_id TEXT,
  outcome TEXT NOT NULL CHECK(outcome IN ('ALLOW','DENY','ERROR','UNKNOWN')),
  safe_code TEXT NOT NULL,
  detail_sha256 BLOB CHECK(detail_sha256 IS NULL OR length(detail_sha256)=32),
  prior_hash BLOB CHECK(prior_hash IS NULL OR length(prior_hash)=32),
  event_hash BLOB NOT NULL CHECK(length(event_hash)=32)
) STRICT;
CREATE INDEX ix_audit_time ON audit_events(utc_time);
CREATE INDEX ix_audit_correlation ON audit_events(correlation_id);
CREATE TABLE backup_records (
  backup_id TEXT PRIMARY KEY,
  generation INTEGER NOT NULL UNIQUE CHECK(generation>=1),
  authority_epoch INTEGER NOT NULL,
  schema_version INTEGER NOT NULL,
  artifact_sha256 BLOB NOT NULL CHECK(length(artifact_sha256)=32),
  recovery_key_id TEXT NOT NULL,
  created_at TEXT NOT NULL,
  verified_at TEXT,
  restore_tested_at TEXT,
  state TEXT NOT NULL CHECK(state IN ('CREATED','VERIFIED','INVALID','EXPIRED'))
) STRICT;
CREATE TABLE recovery_tombstones (
  tombstone_id TEXT PRIMARY KEY,
  entity_kind TEXT NOT NULL CHECK(entity_kind IN ('CLIENT','CREDENTIAL','GRANT','PACKAGE')),
  entity_id TEXT NOT NULL,
  authority_epoch INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  UNIQUE(entity_kind,entity_id,authority_epoch)
) STRICT;
CREATE INDEX ix_tombstones_entity ON recovery_tombstones(entity_kind,entity_id);
CREATE TABLE recovery_operations (
  operation_id TEXT PRIMARY KEY,
  operation_kind TEXT NOT NULL CHECK(operation_kind IN ('BACKUP','RESTORE','MIGRATE','RECONCILE')),
  state TEXT NOT NULL CHECK(state IN ('STARTED','COMMITTED','FAILED')),
  started_at TEXT NOT NULL,
  finished_at TEXT,
  detail_sha256 BLOB CHECK(detail_sha256 IS NULL OR length(detail_sha256)=32)
) STRICT;
CREATE TABLE config_revisions (
  revision_id INTEGER PRIMARY KEY AUTOINCREMENT,
  config_sha256 BLOB NOT NULL CHECK(length(config_sha256)=32),
  created_at TEXT NOT NULL,
  owner_sid TEXT NOT NULL
) STRICT;
INSERT INTO store_metadata(singleton,instance_id,schema_version,authority_epoch,policy_epoch,recovery_generation,created_at)
VALUES(1, :instance_uuid,1,0,0,0,:utc_now);
INSERT INTO schema_migrations(migration_id,checksum,applied_at,app_version)
VALUES(1,:migration_checksum,:utc_now,:app_version);
PRAGMA user_version=1;
COMMIT;
```

## Transaction catalog
All writes gateway-only, one writer connection, `BEGIN IMMEDIATE`, prevalidate inputs, apply changes plus audit event, update `policy_epoch` and `authority_epoch` when authority changes, then COMMIT. Any partial statement failure -> ROLLBACK. No worker launch, network call or owner prompt inside SQL write transaction. All calls using stale epochs must revalidate.
- TX-001 owner enroll client: insert client + credential verifier + audit + increment epoch; plaintext credential returned only once over owner channel after commit. Failed delivery revokes issued credential using a new audited transaction.
- TX-002 rotate/revoke: create successor credential with explicit <=24h overlap or mark old revoked; record tombstone for permanent revoke + increment epoch + audit. Expired and revoked credentials never allowed by restored old DB.
- TX-003 stage/validate/trust/enable/revoke tool: state transition with expected revision, package SHA verification before transaction, policy epoch bump, audit. Tool revocation cancels queued calls and invalidates pending approvals in same transaction where possible.
- TX-004 grant/revoke: client/version current state checked, scope subset validated and grant changed + policy epoch + audit. Revocation tombstone added.
- TX-005 approval creation/decision: pending row + audit; owner approval requires verified admin token and conditional `WHERE state='PENDING' AND expires_at > :now AND revision=:expected` mutation with exactly one row; no client-side authority.
- TX-006 admission: conditional `APPROVED -> CONSUMED` approval update, insert invocation, optional idempotency row and audit in same transaction; zero/multiple updated rows or constraint failure -> rollback. Validate client/grant/version/digest/policy epoch/expiry and argument SHA256 again under writer lock. Non-approval calls insert invocation+audit without approval update.
- TX-007 scheduling/terminal: CAS invocation revision and legal state transition + audit. Terminal states immutable. On restart ADMITTED/QUEUED -> CANCELLED; RUNNING -> UNKNOWN_EFFECT unless independently proven no side effect.
- TX-008 backup: SQLite Online Backup API or locked consistent snapshot captures main DB+WAL; encrypted package and authenticated manifest written/verified outside live store, then backup metadata and audit transaction. Never raw file-copy a live WAL database.
- TX-009 restore: offline validate AEAD, digest, schema, foreign keys and integrity; compare against independently protected latest owner authority epoch/revocation ledger; refuse rollback of revocation/consumed approval. Atomic directory swap with rollback only after validation; no live restore.
- TX-010 audit retention: 90 days, only after verified backup, no deletion of required authority/tombstones; append-only events logically immutable except audited retention compaction. Keep separately protected authenticated audit anchors.
- TX-011 migration: no database reset; verify source schema/checksum, private backup, exclusive gateway maintenance mode, transactional migration+audit+version row, integrity and rollback to validated backup on failure. Never down-migrate blindly.
- TX-012 recovery reconciliation: authority epoch and revocation ledger validated; stalled invocations reconciled with audit and no blind replay.
 
## Recovery anti-rollback boundary
SQLite alone cannot prevent a privileged operator from restoring an old DB snapshot including once-valid credentials and approvals. Therefore an owner-protected **external monotonic authority/revocation checkpoint** is part of C-008 and is mandatory at recovery: encrypted authenticated record of instance ID, latest authority epoch, revoked credential/client/tool/grant IDs, consumed approval IDs and latest audit hash. Advance this checkpoint with each security mutation under a durable outbox/recovery protocol, ensuring failures leave gateway locked for recovery rather than silently succeeding with a stale checkpoint. Never assume local DPAPI is hardware-backed rollback prevention. Lost independent checkpoint is a manual owner recovery event and must revoke/re-enroll clients before service resumes. This feature remains cross-component qualification-dependent.

## Failure and qualification conditions
Q-DB-01 foreign keys/integrity and migration checksum; Q-DB-02 writer contention and rollback under SQLITE_BUSY; Q-DB-03 fault injection at each SQL statement for TX-001–TX-007; Q-DB-04 duplicate approval and idempotency concurrency; Q-DB-05 process kill before/during/after COMMIT; Q-DB-06 snapshot restore and WAL consistency; Q-DB-07 lost checkpoint/rollback attempts; Q-DB-08 redaction and 90-day compaction. Preserve exact SHA, SQLite build/version, OS, structured observed DB evidence and failures. None executed in Phase 0.
