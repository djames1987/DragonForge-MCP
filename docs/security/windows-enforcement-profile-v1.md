# WIN-SEC-003 — Windows 10 enforcement profile and test criteria
Documentation only; not a qualified sandbox. Supersedes conflicting illustrative guidance in WIN-QUAL-001/WIN-SEC-002, retains their WQ-001..012 IDs.

## Supported build gate
Initial release candidate is **Windows 10 22H2 x64 build 19045 only**, Desktop editions Pro/Enterprise/Education individually profiled by edition, UBR, security settings, Python/native runtime and installed patches. All other builds/editions and Windows 11 are `ISOLATION_UNAVAILABLE` until separately qualified. This is a product-support **candidate**, not evidence it works on every patched 19045 computer. API availability must be tested on the exact release build. Windows 10's servicing state and residual unpatched vulnerabilities must be disclosed; no security claim against kernel compromise.

## Owner named pipe security descriptor
Gateway service SID and expected configured owner SID are obtained from trusted OS calls at launch, not string user inputs. Generate SDDL *from the real SID* in this form: `O:<gateway-sid>G:<gateway-sid>D:P(A;;GA;;;<gateway-sid>)(A;;GRGW;;;<owner-sid>)S:(ML;;NW;;;ME)`. This is a candidate for verification, **not a hard-coded universal SDDL**: the mandatory integrity label and owner logon integrity need Win32 conversion and readback. If gateway uses service SID ownership syntax unsupported by deployment mode, fail closed and use specifically approved service account profile; never substitute Everyone/Authenticated Users broad ACE. Check actual security descriptor with `GetSecurityInfo` and token access check on release target. Use `CreateNamedPipeW` with `PIPE_REJECT_REMOTE_CLIENTS`, `FILE_FLAG_OVERLAPPED`, protected random per-install pipe name, explicitly set `SECURITY_ATTRIBUTES` and secure creation. Admin commands require `ImpersonateNamedPipeClient` and `OpenThreadToken`, `GetTokenInformation(TokenUser, TokenStatistics, TokenIntegrityLevel, TokenElevationType)`, expected owner SID and logon AuthenticationId, then `RevertToSelf` in all paths. The owner SID alone is not proof of attended presence; sensitive commands require independent challenge.

## Worker IPC DACL
Workers run in dedicated AppContainer per installed package digest. Bind worker named pipe to gateway plus exact AppContainer SID, with no broad `ALL APPLICATION PACKAGES` ACE. Use descriptor template `O:<gateway-sid>G:<gateway-sid>D:P(A;;GA;;;<gateway-sid>)(A;;GRGW;;;<worker-appcontainer-sid>)S:(ML;;NW;;;LW)`, followed by token, access check and SDDL round-trip verification; if low mandatory integrity label cannot be justified and tested with intended communication, deny. A DACL permits connections; it is not sufficient authentication. On connection verify impersonated token's `TokenIsAppContainer`, `TokenAppContainerSid`, restricted capabilities, integrity, and uniquely bound launch nonce/channel instance. Reject PID-only authority, unexpected SID and inherited handle spoofing.

## Process launch and privilege boundary
CreateAppContainerProfile/DeriveAppContainerSidFromAppContainerName; validate SID equality and declared capabilities. Create `STARTUPINFOEXW` with `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES` and `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, explicit minimal environment and CWD, `EXTENDED_STARTUPINFO_PRESENT | CREATE_SUSPENDED`. CreateProcessW must demonstrate correct sandboxed token on OS build. Set Job Object KILL_ON_JOB_CLOSE and active process/process-memory limits before resumption; reject when job assignment fails including parent nested job. Never regard Job Object as a filesystem/network sandbox. Query `TokenIsAppContainer`, `TokenAppContainerSid`, `TokenCapabilities`, privileges, integrity and job membership, log redacted identity evidence and compare to planned policy. On any mismatch terminate suspended process; do not resume. W0 network-denied and W1 brokered file access only; W2 network and W3 admin remain unsupported.

## Broker/loader
Opaque invocation-scoped capability token is one-use, expiry-limited, policy epoch bound and requires OS-verified peer. Broker resolves trusted allowed root as a handle, enumerates each path component, rejects device names, ADS, reparse points/junctions/symlinks, and uses CreateFileW with FILE_FLAG_OPEN_REPARSE_POINT and GetFileInformationByHandleEx(FileIdInfo)/GetFinalPathNameByHandleW after open; confirm same volume/root and no swap. Rename/delete/create semantics require separate transactionally checked broker operations; never forward unrestricted directory handles. Reject writable module search roots and DLL hijacking; `SetDefaultDllDirectories`, explicit pinned `AddDllDirectory` and immutable package snapshot; dynamic imports must resolve from verified image/package bytes. Untrusted package write after owner trust always invalidates runnable digest. No direct worker reach into gateway data, registry, credential storage or admin pipe.

## Negative fixtures and evidence
WQ-001 AppContainer token and Job Object membership; 002 filesystem DB+secrets access denied by kernel and unchanged hash; 003 registry key access denied; 004 Winsock TCP, UDP and DNS (no AppContainer capability); 005 owner pipe denied; 006 wrong AppContainer SID denied worker IPC; 007 child job escape denied; 008 junction swap no outside file change; 009 modified package refused before launch; 010 crash/timeout kills worker and gateway healthy; 011 permitted broker operations succeed while one-byte-out-of-scope file denied; 012 malicious PATH/DLL import denied. Every fixture must capture exact OS build+UBR, tool and package digest, evaluated SID/DACL, Win32/NTSTATUS code, OS event (ETW/ProcMon) and correlation to gateway audit; a gateway-produced denial JSON **alone never passes**. Each unsupported API or unexpected pass -> disable corresponding untrusted profile. Run only in future authorized development on disposable test user/VM.
