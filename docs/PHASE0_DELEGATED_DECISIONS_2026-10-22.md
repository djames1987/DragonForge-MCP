## DEC-001 — Protocol (prior owner selection, retained)
**Selection:** MCP `2026-07-28` only; modern stateless request semantics; reject older protocol eras and do not auto-fallback. **Reason:** avoid blending legacy session and modern per-request contracts. **Tradeoff:** legacy clients require separately authorized future adapters. Reference: https://modelcontextprotocol.io/specification/2026-07-28 . Must still complete exact C-010 transcripts and status mappings.

## DEC-002 — Client identity and credential lifecycle
**Selection:** owner-enrolled, individually named clients with 256-bit CSPRNG-generated bearer credentials, transmitted only over an authenticated local endpoint. Store keyed HMAC-SHA-256 verifiers under an OS-protected gateway-owned pepper, never raw bearer tokens; identify credential records through non-secret random key IDs (key IDs alone provide no authority). Use constant-time verifier comparison; no identity derived from loopback, Host, Origin, STDIO ancestry, MCP metadata, or display names. Credentials scoped to a single gateway instance/client record. Default 90-day credential lifetime; 24-hour explicit dual-key rotation overlap only when owner requests rotation, with immediate revocation available; bootstrap emergency recovery requires local owner OS-authenticated control plane and cannot recreate grants implicitly. A revoked or expired key fails on the next admission/recheck. The STDIO adapter holds only its own provisioned client secret through a restrictive per-user OS credential store; client text cannot select another principal.
**Alternatives:** mTLS locally (certificate infrastructure overhead); client-asserted name (forgeable); no authentication on localhost (unacceptable). **Risks:** same-user malware can misuse an unlocked session or steal an exposed bearer secret; DPAPI/OS permissions reduce at-rest leakage but cannot eliminate endpoint compromise. **Contracts:** C-001, C-007, C-008, C-009. **Tests:** T-002, T-003, T-005, T-014, T-021; add rotation/race/credential-store negative fixtures. **Rollback:** rotation rollback only within explicitly authorized overlap; revocation never silently undone by a restore.

## DEC-003 — Trusted sensitive-action approval
**Selection:** an independently authenticated, owner-operated `dfmcp approvals` CLI over a restrictive OS-authenticated **local admin-only named pipe**, not the public MCP endpoint. Owner authentication must derive from a validated OS logon token/SID and authenticated pipe peer using impersonation-safe server logic; a bare claimed username, PID, or CLI flag never suffices. Pending approvals are gateway-originated and not secrets conveyed through MCP model text. Confirmation must display canonical tool ID/version/digest, verified client ID, effect/capabilities, exact canonical argument SHA-256, expiry, and a human-readable impact preview generated from reviewed schema/metadata (not untrusted tool prose). An approval record binds gateway-generated 128-bit random nonce, invocation ID, principal, digest, capabilities, argument hash, and expiration (proposed maximum five minutes). Owner denial/expiry is terminal; approval is single-use and atomically consumed in gateway SQLite with invocation admission; timeout, policy/grant change, digest change, or process crash before admitted transaction is fail-closed. Concurrent approval races permit one winner, never double dispatch. No automatic client-side approval or headless fallback.
**Alternatives:** MCP prompt/tool parameter (self-approval attack); browser UI (additional origin/session boundary); secure OS dialog (later optional). **Limitations:** Windows account compromise compromises this local owner boundary; canonical argument encoding and crash/reconciliation remain to be precisely specified in C-006/C-005. **Tests:** T-006,T-013,T-014,T-016 plus OS impersonation and replay negatives.

## DEC-004 — Windows 10 third-party worker confinement
**Selection:** Windows 10 x64 desktop initial target. Third-party workers execute in a **separate low-privilege AppContainer identity** with capability-free baseline (no internetClient/privateNetworkClient by default), restrictive package/data ACLs, a dedicated unprivileged IPC endpoint, a kill-on-job-close Job Object (process count, CPU/memory/time budgets), carefully restricted handle inheritance, and an allowlisted read/write broker for explicitly reviewed capabilities. The trusted gateway is outside the sandbox and performs brokered access only after current grant and path-scope verification; workers never receive direct database or owner credential paths. AppContainer **plus** ACL/IPC checks and Job Objects are complementary, not substitutes. Launch, identity, network and filesystem isolation must be qualified on the actual Windows 10 build and account configuration before enabling any third-party worker. If a confinement guarantee or a required brokered capability cannot be demonstrated, return `ISOLATION_UNAVAILABLE` and do **not** downgrade to a normal subprocess, restricted token alone, or full-trust fallback. No claim is made that AppContainer prevents every kernel, same-user, or authorized-broker exploit.
**Alternatives:** restricted token + ACLs only (weaker/complex network assurance); VM per tool (high operational cost); unrestricted subprocess (rejected). **Limitations:** packaging/AppContainer identity provisioning, desktop compatibility and network capability controls require build-specific investigation; some tools may be unavailable at v1. **Contracts:** C-002,C-003,C-007 and worker-isolation ADR. **Tests:** T-010,T-011,T-020,T-022 including file, network, IPC, handle, registry, junction/race and process escape negatives.

## DEC-005 — Retention, backup and recovery defaults
**Selection:** SQLite WAL with one authoritative writer. Retain security/audit metadata for **90 days** by default, retaining active trust/revocation state regardless of audit age; rotation/compaction only after a verified backup and enforced referential/audit retention constraints. Daily **offline-consistent encrypted local backup** under a separately ACL-protected owner-controlled directory, **30 daily recovery points**, with one weekly restore-verification drill and backup verification on creation; use Windows DPAPI-protected envelope keys bound to the designated recovery owner, plus an owner-controlled, separately protected export/recovery-key procedure to avoid unrecoverable machine/account loss. Restore is an offline privileged operation: checksum/AEAD validation, schema/version validation, integrity check, authoritative principal/revocation checks, atomic cutover and rollback on failure; never silently create an empty authority store if corrupt. Never restore expired/revoked credentials into usable status without deliberate, audited owner recovery reconciliation.
**Provisional measurable qualification targets:** recovery-point objective up to 24h (last validated daily backup), recovery-time objective at most 30 minutes for the defined small reference fixture on the supported hardware, startup recovery reconciliation within 60 seconds for that fixture. These targets are *agent-selected design targets*, not measured achievements. If backups cannot be validated or key recovery is unavailable, report degraded/recovery status and fail closed for security-sensitive operation. **Alternatives:** unencrypted copies (reject leakage), cloud backups (not local-first), indefinite retention (privacy/volume). **Limitations:** 90-day audit retention may not satisfy external compliance requirements; owner should configure longer policy if needed. **Contracts:** C-005,C-008,C-009; **tests:** T-006,T-016,T-017,T-023,T-025 plus rollback and backup-key-loss negatives.

## DEC-006 — Package signing/provenance (prior owner selection, retained)
**Selection:** mandatory complete-package SHA-256 fingerprint and exact owner trust; publisher certificate/signature not mandatory. Every byte change invalidates trust. Trust/enablement/grants/approval/confinement are independent. **Limitation:** a digest proves equality to selected content, not authorship or safety. Canonical digest algorithm and TOCTOU protections remain mandatory C-002 freeze blockers.
